水蛋一家人的旅程

记录一家人走过的路和拍下的照片。一个不依赖构建工具的静态站点：数据放在 data.js，
页面用原生 JS + Leaflet 渲染，改数据不用再跑 R 脚本。

打开方式

  • 直接双击 index.html 就能看（数据走 <script src="data.js">，不受 file:// 限制）。
  • 想用服务器也可以：python3 -m http.server 8000，然后开 http://localhost:8000/。
地址 用途
index.html 地图 / 照片墙 / 足迹时间线 / 统计汇总
admin.html 添加和编辑数据

四个视图

视图 内容
地图 足迹点按人物用不同头像标记，行程按年份分层；点标记看照片和故事
照片 瀑布流照片墙，可按人物、年份筛选，点开可放大翻页
足迹 按年份倒序的时间线，支持关键词搜索
统计 累计里程、足迹数、照片数、到访城市、年度里程/足迹柱状图、人物分布、最远行程、抵达边界

怎么添加足迹和照片

打开 admin.html：

  1. 加足迹点：在地图上点一下 → 自动填好经纬度 → 填标题、人物、日期、地点
    → 照片框里每行贴一个地址 → 保存。
    • 也可以先用搜索框查地点（如「杭州西湖」）自动定位。
    • 照片既可以是网络地址，也可以是仓库里的相对路径 photos/xxx.jpg；
      点「选择本地照片…」会自动填成 photos/文件名，把照片丢进 photos/ 目录就行。
    • 一个足迹可以配多张照片（旧版只能一张）。
  2. 加行程：切到「行程路线」→ 点「开始绘制」→ 在地图上依次点途经点 → 结束绘制
    → 填标题、年份、起终点 → 保存。里程会按大圆距离自动算出来。
  3. 保存：点右上角「保存为 data.js」。
    Chrome / Edge 会弹出保存对话框，直接选仓库里的 data.js 覆盖即可；
    其他浏览器会下载一个 data.js，手动放回仓库根目录。

编辑过程中的改动会先存进浏览器本地草稿，中途关掉页面也不会丢；
没导出前右上角会亮一个小圆点。点「放弃修改」可以丢掉草稿重新载入。

data.js 结构

window.JOURNEY_DATA = {
  "meta":   { "title": "…", "subtitle": "…", "updated": "2026-09-25" },
  "people": [ { "id": "xinrui", "name": "新锐", "color": "#18BC9C", "icon": "assets/img/icon-xinrui.png" } ],
  "places": [ { "id": "p001", "title": "…", "person": "xinrui",
                "lng": 122.11, "lat": 37.50, "date": "2021-06-18",
                "place": "威海市妇幼保健院", "city": "威海市",
                "note": "", "photos": ["https://…/a.jpg"], "fields": { "体重": "3.7kg" } } ],
  "routes": [ { "id": "r001", "title": "…", "year": 2021, "color": "#18BC9C",
                "weight": 8, "date": "2021-08-31", "from": "威海", "to": "阜阳",
                "lines": [ [[lng,lat], [lng,lat], …] ], "distance": 989.6 } ]
};

坐标是 WGS84。高德底图用的是 GCJ-02，叠加时页面会自动换算，
所以点在图上的位置是对的（旧版少了这一步，每个点都偏几百米）。

⚠️ 两个坑，改代码时务必注意

  1. 坐标顺序：JSON 里的坐标一律是 GeoJSON 顺序 [lng, lat]，
    而 Leaflet 的 L.marker / L.polyline / L.latLngBounds 要的是 [lat, lng]。
    两者搞反的症状是：标记飞出地球、折线立成竖线、fitBounds 把视图中心算到北极。
    所以喂给 Leaflet 的坐标一律走 Geo.toLatLng(lng, lat, gcj)，不要手写数组。
  2. 容器尺寸：Leaflet 在 display:none 的容器上会量到 0×0，
    fitBounds 因此算不出缩放、只能回落到 minZoom，结果所有足迹挤成一小团。
    所以必须先 showView('map') 再 initMap()，并在窗口 resize 时 invalidateSize()。
  1. 地图合并同地标记：地图上同一个经纬度 + 同一个 type（人物）的多张照片只画
    一个标记，点开弹窗里用缩略图网格列出该处全部照片（点缩略图可放大看全部）。
    照片墙、时间线、统计里仍然显示全部足迹与照片，不受影响。这样照片多时地图也不会卡。

从旧版数据重新迁移

旧版的 data.xlsx + routedata.xlsx + route/*.rds 都还在，需要重跑时：

python3 -m venv .venv && .venv/bin/pip install pandas openpyxl rdata
.venv/bin/python3 tools/migrate.py            # 生成 data.js
.venv/bin/python3 tools/migrate.py --json     # 另外再导出一份 data.json 给其它工具用

会把 popup 里的 HTML 表格解析成结构化字段、日期归一成 YYYY-MM-DD、
按大圆距离算出每条行程的里程，并对折线做抽稀（约 80 米精度）以控制文件体积。
route/ 目录里没被 routedata.xlsx 登记的 3 条路线也会一并收进来（年份留空待补）。

旧版 R 脚本仍然保留，但输出已改到 legacy_leaflet.html，不会再覆盖 index.html。

部署

静态文件，推到 GitHub 上开 Pages 即可（根目录为仓库根）。
照片放仓库会让体积变大，量大的话建议继续用图床，填完整 URL 就行。

想把「服务器真正需要的文件」单独抽出来，用 tools/deploy.py 一键收集到 public/：

python3 tools/deploy.py            # 收集 index.html / admin.html / assets / data.js → public/
python3 tools/deploy.py --build    # 先重新生成 data.js，再收集

public/ 是构建产物，每次运行都会清空重建，别在里面手改。可直接上传到任意静态服务器
（GitHub Pages 把 public/ 内容设为 Pages 源；Vercel/Netlify 构命令填 python3 tools/deploy.py、发布目录填 public）。
